# `/admin/users` 页面合同

## 基本信息

- 目标路由：`/admin/users`
- 源码入口：`app/pages/admin/users.vue`
- 暗色原型：`/home/vhhg/workspace/www/taste/v2-kimi-user.html`
- 亮色版本：使用项目双主题 Token 生成，不另造一套页面结构
- 基准视口：`375px`、`1440px`、`1920px`
- 依赖接口：
  - `GET /api/admin/users`
  - `GET /api/admin/groups`
  - `GET /api/admin/plans`
  - `GET /api/admin/users/:id`
  - 用户创建、编辑、重置密码、删除和套餐分配接口

## 页面结构

1. 页面标题区：`IDENTITIES`、用户管理、页面说明、创建用户。
2. 筛选工具栏：搜索、角色、状态、分组、结果数量、清除筛选。
3. 用户表格：用户、角色/状态、分组、套餐、Hub Key、最后登录、操作。
4. 用户详情抽屉：身份摘要、请求/Token/成本指标、Hub Keys、最近活动。
5. 创建/编辑用户弹窗：身份信息、角色和状态、分组/套餐访问配置、错误反馈、底部操作。
6. 删除确认：沿用公共确认对话框，仅更换公共动效后继承。

## 业务边界

- 保留现有接口、权限、路由和提交载荷。
- 页面角色只提供“用户”和“管理员”两项。后台仍可能返回 `super_admin`、`operator` 或 `auditor` 等历史角色；这些角色统一展示为“管理员”，编辑时在未切换为“用户”的情况下保留原始角色值。
- 页面状态只提供“启用”和“停用”两项，使用开关控件。后台历史 `locked` 状态按“停用”展示，编辑保存时归并为 `disabled`。
- 创建用户时密码必填；编辑用户时始终显示密码输入框，留空不修改，非空才调用重置密码接口。
- 用户管理中的密码重置对当前登录管理员也适用；不再跳转到单独的修改密码页面。
- 普通用户继续使用默认分组和默认套餐逻辑。
- 管理角色继续支持多个 Hub 分组。
- 有 Hub Key 的用户不能删除，最后一个超级管理员不能删除。
- 当前页面不自行增加用户字段或统计字段。
- 原型示例数据只用于结构对照，页面显示真实接口数据。

## 动效边界

- 页面标题、工具栏和表格使用页面专属的顺序入场动效。
- 遮罩淡入、弹窗淡入并上移缩放、抽屉从右侧滑入属于公共层动效。
- 公共层动效必须支持 `prefers-reduced-motion: reduce`。
- 业务列表行只保留轻量悬停和按压反馈，不使用大面积持续动画。

## 必须覆盖的状态

- 启用用户列表。
- 搜索和角色、状态、分组筛选后的列表。
- 无匹配用户的空状态。
- 用户详情加载中、详情内容为空和详情接口错误。
- 创建用户、编辑用户、保存中和表单错误。
- 编辑用户时密码输入框可留空，角色只有用户/管理员，状态使用启用/停用开关。
- 删除确认、删除中和删除失败。
- 长用户名、邮箱、Key 名称和最近活动请求 ID。
- `375px` 下的筛选区、表格横向滚动、抽屉和弹窗。
- 暗色和亮色主题。

## 页面专属规则

- 表格在宽屏下填满页面容器，数据列不人为压缩到无法扫描。
- 顶部角色、状态和分组筛选使用页面内的紧凑选项面板，不使用无法统一主题的系统原生下拉面板；必须保留完整键盘与焦点交互。
- 用户身份区域保留主名称、用户名和邮箱的层级；只在表格容器需要时滚动，不以页面级截断代替布局。
- 详情抽屉宽度、身份区、三项指标、Key 列表和最近活动按原型的层级实现。
- 创建/编辑弹窗在桌面采用左右访问配置布局，在窄屏转为单列滚动。

## 已确认的原型差异

- 原型只有暗色文件；亮色使用同一 DOM 和项目 Token，不复制原型中的硬编码暗色值。
- 原型中的示例用户、Key、请求和日期必须替换为接口数据。
- 原型使用的 Lucide 图标由项目现有 `@tabler/icons-vue` 对应图标替代，图标语义和尺寸保持一致。
